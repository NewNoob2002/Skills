# W03 新模块设计与实现

在已批准的架构内新增模块或功能。Developer 的通用流程见 [workflow.md](workflow.md) §4，任务契约格式见 [workflow.md](workflow.md) §6。

## 概要

| 项 | 内容 |
| --- | --- |
| 触发 | 新增模块、功能或公共 API |
| 输入 | 需求；所属层与接口；适用规则（`profiles/<id>.yaml` 与 `standards/rules.yaml`） |
| 前置条件 | 已评估架构 delta（[workflow.md](workflow.md) §1）；涉及接口、并发或内存布局时已获得 Delta 批准 |
| 角色 | Developer 实现；QA 先写验收测试，期望值来自需求（`GEN-006`）；接口需要变更时交回 Architect |
| 产物 | 一页契约（职责、接口、错误、时延、所有权）、实现、单元测试、验证报告 |
| 人工审批 | 公共接口变化、新增依赖、资源预算变化 |

## 步骤

1. 写契约：职责、公共接口、错误语义、时延与并发约束、资源所有权。
2. QA 按契约编写测试，并冻结测试所在的提交（task contract 的 `frozen_inputs`）。测试由 QA 编写，不由实现者编写。
3. 核实硬件假设（`GEN-002`）。
4. 窄范围实现，遵守 profile 规范；生成代码只改保护区（`GEN-007`）。
5. 审计故障路径：有界等待、超时时钟有效、tick 回绕（`GEN-009`），外部输入校验（`GEN-010`）。
6. 运行机械门禁：格式、静态检查、`arch_lint`、编译告警。
7. QA 运行冻结的测试。实现者不得为了让测试通过而修改冻结测试；测试本身有误时记录原因，由 QA 修改。
8. 按 SKILL.md §5 报告。

## 检查点

| 检查点 | 通过标准 | 不通过时 |
| --- | --- | --- |
| 契约 | 接口、错误、时延、所有权四项齐全 | 回到步骤 1 |
| 测试冻结 | 测试提交早于实现提交，或由独立会话/人员编写 | 验收结论记为 `BLOCKED`（缺少独立验证） |
| 门禁 | 没有新增告警或违规 | 修复后重跑 |
| 冻结测试 | 全部通过，且测试文件没有被实现者改动 | FAIL |

## 通过与失败

- **PASS**：冻结测试全部通过、门禁没有新增发现、审查没有 `mandatory` 违规。
- **FAIL**：上述任一项不满足。
- **BLOCKED**：没有独立的验证者，例如测试与实现出自同一角色步骤、事后补写。
