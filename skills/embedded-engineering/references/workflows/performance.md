# W07 性能与资源分析

只看同一工具链、同一选项下的 A/B 增量。方法细节见 [verification/cpp-testing.md](../verification/cpp-testing.md) §6，栈与故障分析见 [verification/debugging.md](../verification/debugging.md)。

## 概要

| 项 | 内容 |
| --- | --- |
| 触发 | 资源预算检查、优化之前、发布之前、评估 C++ 特性 |
| 输入 | 基线与候选的 ELF/map、链接脚本、预算文件；可选的目标板 |
| 前置条件 | 两次构建的工具链、选项和配置完全一致，只有被评估的改动不同 |
| 角色 | Developer 负责测量；QA 复核测量方法与结论 |
| 产物 | Flash/RAM 增量表、符号 top-N、栈估算、运行时数据（有板时）、与预算的对比结论 |
| 人工审批 | 上板测量涉及 flash，需要授权（`GEN-001`） |

## 步骤

1. 固定基线与候选的提交、工具链版本和编译选项，写入报告。
2. 体积：运行 `scripts/cpp_cost.py diff <base.elf> <new.elf>`，得到段增量与符号增量。
3. 禁止的运行时：运行 `scripts/cpp_cost.py check <elf> --tier <Tn> --budget <budget.json>`（`CPP-001` 至 `CPP-009`、`TEST-004`）。
4. 栈：用 `-fstack-usage` 生成各函数栈帧，结合调用图估算最坏深度；递归和间接调用无法静态确定，标为 `UNKNOWN`。
5. 运行时（有板时）：用 DWT `CYCCNT` 或 GPIO 打点测 ISR 与关键路径（`ISR-006`），用 RTOS 水位线测任务栈余量（`RTOS-002`）。
6. 与预算逐项比较。

## 检查点

| 检查点 | 通过标准 | 不通过时 |
| --- | --- | --- |
| 同条件 | 两次构建只有被评估的改动不同 | 重新构建 |
| 数值来源 | 每个数字都附有产生它的命令及其输出 | 删去该数字 |
| 栈 | 估算中每个 `UNKNOWN` 都有原因，并有运行时水位线复核 | 标 `NOT_RUN` |
| 预算 | 每项都有测量值和预算值 | 补齐 |

## 通过与失败

- **PASS**：所有预算项都有测量值，且都在预算之内。
- **FAIL**：任一项超出预算。
- 无法测量的项（例如没有板子时的时序）标 `NOT_RUN`；微基准数据只能作为先验，不能代替项目 ELF 的实测。
