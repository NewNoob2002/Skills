# W08 回归测试

判断标准是与基线比较：既不能出现新的 FAIL，也不能丢失覆盖。

## 概要

| 项 | 内容 |
| --- | --- |
| 触发 | 合并前；升级工具链、SDK 或 RTOS 后；修复缺陷后 |
| 输入 | 改动范围、现有测试集、基线结果（上一次 PASS 的提交及其结果） |
| 前置条件 | 基线结果可以获得；没有基线时先建立基线，本次结论为 `BLOCKED` |
| 角色 | QA 负责执行与判定；Developer 负责修复 |
| 产物 | 基线与当前结果的对比表（按证据级别）、新失败清单、跳过清单 |
| 人工审批 | 修改或删除既有测试需要说明理由并获批准；放宽任何门禁需要批准 |

## 步骤

1. 确定影响范围：从改动文件找到依赖它的模块（构建依赖图，或 `arch_lint` 的 include 关系）。
2. 选择测试：先跑受影响的定向测试，再跑全量。
3. 修复缺陷时，先写复现测试，确认它在修复前失败。
4. 按证据级别依次运行：host → 静态 → 目标构建 → 仿真 → HIL。
5. 与基线比较：找出新增的 FAIL，以及从 PASS 变成 `NOT_RUN` 的项目（覆盖丢失）。
6. 工具链或编译选项变化时，运行 `scripts/bench/run.sh` 并更新 [cpp/features.md](../cpp/features.md) §4。
7. 报告结果。

## 检查点

| 检查点 | 通过标准 | 不通过时 |
| --- | --- | --- |
| 复现测试 | 修复前 FAIL、修复后 PASS | 复现测试无效，重写 |
| 跳过 | 每个跳过的测试都有原因，且原因与基线一致 | 当作覆盖丢失处理 |
| 不稳定测试 | 重跑次数与每次结果都记录在报告中 | 不得用“重跑通过”掩盖失败 |

## 通过与失败

- **PASS**：没有新增 FAIL，没有覆盖丢失。
- **FAIL**：有新增 FAIL，或有未说明原因的覆盖丢失。
- **BLOCKED**：缺少基线。
