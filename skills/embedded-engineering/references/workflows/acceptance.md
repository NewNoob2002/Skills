# W10 最终工程质量验收

验收者必须独立于实现者。验收结论只能基于验收者重新运行得到的证据，不能直接复用作者给出的结果。

## 概要

| 项 | 内容 |
| --- | --- |
| 触发 | 里程碑或发布前的最终验收 |
| 输入 | 需求与验收标准、各阶段报告、构建产物、测试结果、偏离记录 |
| 前置条件 | 实现已冻结（记录提交 SHA）；验收者独立于作者 |
| 角色 | QA（独立）主导；Architect 确认实现与已批准的架构一致；用户或负责人最终签字 |
| 产物 | 验收报告：需求追溯（需求 → 测试 → 结果）、按证据级别的结果、规则合规情况、资源与时序余量、已知问题、`NOT_RUN`/`BLOCKED` 清单 |
| 人工审批 | 最终签字必须由人完成；任何偏离都需要批准 |

## 步骤

1. 冻结：记录提交 SHA、工具链版本、构建配置。
2. 建立需求追溯矩阵：每条需求至少对应一项证据。
3. 由验收者重新运行全部自动门禁，不复用作者的输出。
4. 审查 `mandatory` 规则合规情况（[verification/review-checklist.md](../verification/review-checklist.md)）；偏离必须有批准记录。
5. 汇总资源与实时性结果（W07）。
6. 汇总硬件证据：HIL 与实测结果；缺失的项标 `NOT_RUN`，并评估对验收标准的影响。
7. 给出结论。

## 检查点

| 检查点 | 通过标准 | 不通过时 |
| --- | --- | --- |
| 独立性 | 验收者不是实现者，也不是同一角色步骤 | `BLOCKED` |
| 追溯 | 每条需求都有证据及其状态 | 补证据，或标为未覆盖 |
| 门禁重跑 | 每项门禁都由验收者执行并记录了输出 | 重跑 |
| 偏离 | 每个 `mandatory` 违规都有批准的偏离记录 | FAIL |

## 通过与失败

- **ACCEPT（PASS）**：每条需求都有 PASS 证据；`mandatory` 违规为零，或都有批准的偏离；没有影响验收标准、又未作解释的 `NOT_RUN`/`BLOCKED`。
- **REJECT（FAIL）**：存在需求失败，或存在未批准的 `mandatory` 违规。
- **BLOCKED**：验收者不独立，或关键证据缺失。
- 最终签字由人完成；Agent 只给出建议结论。
