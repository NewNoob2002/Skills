# W06 测试用例生成

测试的期望值来自规格，不来自实现（`GEN-006`）。框架按 profile 选择（`TEST-001`）：C 用 [verification/ceedling.md](../verification/ceedling.md)，C++ 用 [verification/cpp-testing.md](../verification/cpp-testing.md)，Zephyr 用 ztest。

## 概要

| 项 | 内容 |
| --- | --- |
| 触发 | 为模块补测试、为新功能写测试、为缺陷写复现测试 |
| 输入 | 需求或规格、接口头文件（不需要实现代码）、profile |
| 前置条件 | 测试框架已确定；每个期望值都有来源 |
| 角色 | QA 编写测试；Developer 不参与设定期望值 |
| 产物 | 测试文件、需求到用例的追溯矩阵、mock/fake、运行结果 |
| 人工审批 | 一般不需要；引入新框架或新依赖时需要 |

## 步骤

1. 从需求中提取可观测的行为：正常路径、参数错误、依赖错误、边界、超时、恢复（`TEST-002`）。
2. 为每个期望值找来源：规格、数据手册、标准测试向量。不得运行实现、再把它的输出当作期望值。
3. 选择接缝：C 用 CMock（[verification/ceedling.md](../verification/ceedling.md) §4）；C++ 优先编译期 Fake（`TEST-003`，[verification/cpp-testing.md](../verification/cpp-testing.md) §3）。
4. 编写用例：一个用例只测一个行为，用例名描述该行为。
5. 确认用例确实能失败：在实现之前运行（此时应当失败），或对实现注入缺陷做变异检查。
6. 运行测试并报告结果。

## 检查点

| 检查点 | 通过标准 | 不通过时 |
| --- | --- | --- |
| 追溯 | 每条需求至少对应一个用例 | 补用例，或标为未覆盖 |
| 期望值来源 | 每个断言的期望值都能指回规格 | 改写断言 |
| 能失败 | 至少做过一次“实现前运行”或变异检查，并观察到失败 | 用例无效，重写 |
| 隔离 | 用例之间不共享可变状态，执行顺序无关 | 修复 |

## 通过与失败

- **PASS**：追溯矩阵中没有未覆盖的需求（有意不覆盖的写明理由）；用例能失败；测试已运行。
- **FAIL**：存在无法失败的用例，或期望值来自实现。
- 框架未安装、未能运行时报告 `NOT_RUN` 并写明原因。
