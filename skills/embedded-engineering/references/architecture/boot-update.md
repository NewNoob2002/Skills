# 启动链与固件升级

适用于 `mcu-baremetal`、`mcu-rtos`、`zephyr`。涉及 Flash 擦写、option bytes、读保护、安全启动配置的任何操作都属于硬件动作，必须先取得授权（`GEN-001`）。MCUboot 的行为以其官方文档与所用版本为准。

## 1. 启动链

- 第一级 bootloader 保持最小、不可在现场升级；需要升级 bootloader 时采用两级结构，由不可变的第一级校验第二级。
- bootloader 不初始化应用所需的外设，跳转前恢复它改动过的时钟、中断和外设状态（关中断、清除挂起位、重定位向量表、设置 MSP）。
- 应用镜像头包含版本号、大小、目标板标识与兼容性信息；bootloader 拒绝不匹配的镜像。

## 2. 镜像校验与防回滚（`BOOT-001`、`BOOT-003`）

- 每次启动都在跳转前校验镜像：至少校验哈希；量产设备校验签名（如 ECDSA P-256、Ed25519），公钥存放在只读区域。
- 校验失败时不跳转：尝试另一个槽，或停在恢复模式。
- 防回滚：镜像携带单调递增的安全计数器，bootloader 拒绝低于已记录值的镜像；计数器存放在不能被应用随意写的区域（OTP、受保护的 Flash 区）。写 OTP 不可逆，必须授权。
- 签名私钥不进入仓库、构建日志或 CI 明文变量；存放在凭据存储、HSM 或签名服务中，CI 只调用签名接口。

## 3. 升级流程与掉电安全（`BOOT-002`）

| 方案 | 特点 | 代价 |
| --- | --- | --- |
| 双槽交换（MCUboot swap-using-scratch / swap-using-move） | 可回滚；交换状态持久化，掉电后可以继续 | 需要第二个槽（及 scratch 区），交换过程有 Flash 磨损 |
| 仅覆盖（overwrite-only） | 简单，空间小 | 不能回滚 |
| 直接执行（direct-xip） | 两个槽轮流作为执行槽，无需交换 | 镜像需要按槽地址链接，或使用位置无关代码 |

- 在任意时刻掉电都必须能恢复：交换或写入的进度要持久化，下次启动时继续或回退。
- 新镜像先以“测试”方式启动，通过自检后才确认（MCUboot 在应用中调用确认接口，如 Zephyr 的 `boot_write_img_confirmed()`）；未确认就复位时回滚到旧镜像。
- 自检要覆盖关键功能（通信、存储、看门狗），而不只是“能启动”。
- 下载过程中分块校验（如每块 CRC），完成后校验整个镜像的哈希；空间不足或校验失败时保留旧镜像不动。
- 升级期间看门狗仍然有效，擦写 Flash 的耗时要计入喂狗间隔。

## 4. Flash 擦写约束

- 擦除粒度、写入对齐与最小写入单位、带 ECC 的 Flash 是否允许重复写同一位置、擦写期间能否从同一 bank 取指：全部以参考手册为准，并写进驱动注释。
- 在同一 bank 中执行代码的同时擦写该 bank，通常会使 CPU 停顿或出错；需要时把擦写函数放到 RAM 中执行，或使用双 bank。
- 掉电期间正在写入的块视为损坏，必须能够通过校验检测出来。

## 5. 验证

- host 测试：镜像头解析、版本比较、状态机（[architecture/state-protocol-fault.md](state-protocol-fault.md) §1）。
- 故障注入（需要授权并在开发板上进行）：在交换的不同阶段断电，验证都能恢复；写入损坏的镜像，验证会被拒绝；写入低版本镜像，验证防回滚生效。
- 无法执行时，在报告中把对应项标为 `NOT_RUN`，并说明风险。
