# 状态机、通信协议、超时、断言、日志与故障恢复

适用于所有 profile 中的 C/C++ 业务与驱动代码。Zephyr 与 Linux 内核优先使用平台自带的设施（`LOG_*`、`dev_err`、`WARN_ON_ONCE`），本文件给出与平台无关的原则。

## 1. 状态机（`FSM-001`）

- 状态与事件都用枚举（C 用 `enum`，C++ 用 `enum class`），状态转移集中写在一个转移表或一个 `switch` 中，不要分散在多个回调里。
- 每个状态都显式处理“意外事件”：记录日志并进入定义好的错误处理，不得静默丢弃，也不得落到未定义的状态。
- 时间也作为事件输入（定时器到期产生事件），状态处理函数中不阻塞、不轮询等待。
- 入口动作与出口动作只在转移时执行一次，并且可以单独测试。
- 状态机由单一上下文驱动（一个任务或一个主循环）；ISR 只投递事件（`ISR-001`）。
- C++：`std::variant` + `std::visit` 或 `enum class` + `switch` 都可以，开销见 [cpp/features.md](../cpp/features.md) §3；模式见 [cpp/patterns.md](../cpp/patterns.md) §9。

## 2. 通信协议解析（`PROTO-001`、`PROTO-002`）

- 分帧：明确帧头、长度字段、最大帧长和校验方式。先校验长度字段不超过最大帧长和剩余缓冲区，再访问缓冲区。
- 校验通过前不执行命令、不修改状态；校验失败时丢弃该帧并计数。
- 重新同步：出现错误后丢弃字节直到下一个帧头，不要清空整个缓冲区导致后续帧丢失。
- 字节序显式转换：用移位组装，或用 `memcpy` 到本地变量后转换。不要把结构体指针覆盖到接收缓冲区上：缓冲区可能未对齐，而且结构体填充与位序由实现定义（`C-008`）。
- 超时：分别定义字节间超时和整帧超时，超时后丢弃半帧。
- 解析器写成纯函数（输入字节、输出事件），这样可以在 host 上用规格中的测试向量测试（`GEN-006`）。

## 3. 超时与重试（`GEN-009`）

- 用单调时钟（系统 tick 或硬件计数器）计时，不要用可能被校准或调整的日历时间。
- 比较时用无符号差值：`(uint32_t)(now - start) >= timeout`，这样能正确处理计数器回绕。
- 确认超时所用的时钟在当前阶段有效：启动早期 tick 可能尚未运行，低功耗模式下某些计数器会停止。
- 重试有上限并带退避；超过上限后上报明确的错误码，而不是无限重试。

## 4. 错误码与断言（`ERR-001`）

- 错误码：MCU 项目用一个项目级枚举（如 `proj_err_t`，C++ 中为 `enum class Status`）；Zephyr 与 Linux 用负 errno（`ZEP-005`）。错误码向上传播，由能做出决策的层处理。
- 断言只用于程序员错误（不可能发生的状态、违反前置条件的内部调用）。外部输入、硬件错误、超时都是运行期错误，必须返回错误码，不能用断言处理。
- 发布构建中的断言失败：记录现场（[verification/debugging.md](../verification/debugging.md) §5），进入安全态，再复位或由看门狗复位；不要直接把断言编译成空操作，然后带着已损坏的状态继续运行。
- 编译期能检查的条件用 `static_assert`（C11 `_Static_assert`）。
- 断言表达式不得有副作用。

## 5. 日志

- 分级（错误 / 警告 / 信息 / 调试），在编译期裁剪调试级。
- ISR 中不格式化输出（`ISR-001`）：写入环形缓冲区，由低优先级任务格式化后输出；或使用令牌化日志（如 `pw_tokenizer`），把格式字符串留在主机侧。
- 限速：同一错误在短时间内重复出现时只记录次数，避免日志拖慢系统。
- 日志不是故障记录：复位后需要保留的信息写入故障记录（§6）。

## 6. 故障恢复（`FAULT-001`）

- 先分类：瞬态（总线噪声、单次超时）→ 有限次重试；持续（器件无响应）→ 降级运行或隔离该功能；致命（存储损坏、断言失败）→ 进入安全态后复位。
- 每个执行器都要定义安全态（输出关闭或保持在已知安全值），并在软件之外由硬件保证（例如看门狗复位后的引脚默认状态）。
- 记录复位原因与故障现场，启动时上报（[verification/debugging.md](../verification/debugging.md) §5）。
- 看门狗只在各子系统都有进展时才喂狗（`RTOS-005`）。
- 防止复位循环：记录连续故障复位的次数，超过阈值后停在最小安全模式，等待人工处理。
