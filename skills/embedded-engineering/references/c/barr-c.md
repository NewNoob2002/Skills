# BARR-C:2018 检查基线

- 标准原文（免费 PDF/在线版）：<https://barrgroup.com/embedded-c-coding-standard>。下文规则是**意译摘要**，有疑问以原文为准。
- 官方 enforcement kit（MIT，Barr Group）：<https://github.com/netrinomike/barr-c>，本技能在 `assets/barr-c/` 与 `scripts/barrc/check.sh` 中附带其 2018 版副本。
- **只适用于 C 文件**（`.c` 与只含 C 构造的 `.h`）。C++ 文件见 [cpp/coding.md](../cpp/coding.md)，二者的对照见 [profiles.md](../profiles.md) §5。
- **技能默认补充规则（`DOC-001`，不是 BARR-C 原文）**：所有新增自有 C 函数与 C 头中的函数声明必须有 Doxygen，声明或定义择一，不重复；类级/文件级注释不替代。默认英文，项目可在 `AGENTS.md` 指定其他语言；按接口需要说明参数、返回值、错误语义、ISR/线程上下文和所有权。BARR-C 的注释规则（§2）仍然同时适用。
- 2018 版共 167 条，其中 45 条标为 **bug-killing**（下表标 ★）。kit 机械门禁覆盖 61 条，其余约 100 条需要代码审查。

## 1. 适用方式

| Profile | 安全核心（§2） | 格式/命名层（§3） | 门禁（§4） |
| --- | --- | --- | --- |
| `mcu-baremetal`、`mcu-rtos` | 全部 | 全部 | 全部 |
| `linux-userspace` | 全部 | 项目未定义风格时采用 | 采用格式层时启用 |
| `zephyr`、`linux-kernel` | 仅与官方规范不冲突的条目（见 [profiles.md](../profiles.md) §3） | **不适用** | 只用编译告警；格式走官方工具 |

## 2. 安全核心（与格式无关）

| 规则 | 要点 |
| --- | --- |
| 1.1.a | 以 C99 编写；用 `-std=c99` 锁定方言（新版 GCC 默认 GNU C23）。项目已选用更新标准时按项目 |
| 1.1.c / 1.1.d | 不用私有关键字扩展和 `#pragma`（除非隔离并记录）；不用 `#define` 重命名关键字或改变语言 |
| 1.4.a ★ / 1.4.b | 不依赖运算符优先级；`&&`、`||` 的非单一标识符/常量操作数加括号 |
| 1.6.a | 每个强制类型转换配注释，说明为何数值范围安全 |
| 1.7.a / 1.7.b | 不用 `auto`、`register` |
| 1.8.a ★ | 模块外不需要的函数和变量一律 `static` |
| 1.8.b ★ | `const` 用于：初始化后不变的变量、不应修改的引用参数、不应修改的结构成员、代替 `#define` 的强类型常量 |
| 1.8.c ★ | `volatile` 用于：ISR 与主线共享的全局变量、内存映射外设寄存器指针、延时循环计数器。**线程间共享数据不得依赖 `volatile`**（2018 版 1.8.c.ii 的该用法已撤回），用 OS 原语或 `_Atomic` |
| 2.1.b ★ | 注释中不出现 `/*`、`//`、`\` |
| 2.1.c ★ | 不注释掉代码；临时禁用用 `#if 0`，调试代码用条件编译并标记 |
| 2.2.g ★ | 所有假设写在注释里 |
| 2.2.i | 用 `WARNING:`（改动有风险）、`NOTE:`（解释原因）、`TODO:`（未完成）标记 |
| 4.2.b | 每个头文件有预处理 guard |
| 4.2.c.ii | 头文件中不分配任何变量存储 |
| 4.2.d | 公共头不包含私有头 |
| 4.3.c ★ | 每个 `.c` 包含同名 `.h`，以便编译器校验原型 |
| 4.3.d / 4.3.f | 不用绝对路径包含；不 `#include` `.c` 文件 |
| 5.2.a ★ | 整数宽度重要时用 `<stdint.h>` 定宽类型 |
| 5.2.c ★ | `char` 只用于字符与字符串 |
| 5.3.a | 位域不用有符号类型 |
| 5.3.b ★ | 位运算符（`& \| ~ ^ << >>`）不作用于有符号操作数 |
| 5.3.c ★ | 比较与算术中不混用有符号与无符号 |
| 5.4.a / 5.4.b | 尽量避免浮点；必须用时单精度常量带 `f` 后缀，确认编译器支持所需精度，用 `isfinite()` 检查结果 |
| 5.4.b.iv ★ | 永不对浮点做 `==`/`!=` 比较 |
| 5.5.a ★ / 5.5.b ★ | 映射硬件或通信帧的结构体：防止编译器插入填充、改变位序（用 `static_assert(sizeof...)` 校验） |
| 5.6.a / 5.6.b | 布尔用 `bool`；非布尔值转布尔用关系运算（`(count > 0U)`）而不是隐式转换 |
| 6.1.a ★ / 6.1.b ★ / 6.1.c | 函数名不与任何标准语言关键字、C 标准库函数冲突；不以下划线开头 |
| 6.2.d ★ / 6.2.e ★ | 公共函数在头文件中有原型；私有函数 `static` |
| 6.2.f | 参数显式声明且命名有意义；有意不用的参数用 `(void)param;` |
| 6.3.a ★ | 能写成函数就不用带参宏 |
| 6.3.b ★ | 带参宏：整体加括号、每个参数加括号、每个参数只用一次、不含 `return` 等控制转移 |
| 6.5.c ★ | ISR 不能被其他软件意外调用 |
| 7.1.a ★ / 7.1.b ★ | 变量名不与关键字、标准库变量名冲突 |
| 7.2.a ★ | 所有变量使用前初始化 |
| 7.2.d | 尚无地址的指针初始化为 `NULL` |
| 8.2.c ★ | `if`/`else if` 条件中不赋值 |
| 8.3.b | 每个 `switch` 有 `default` |
| 8.3.c | 有意 fall-through 必须注释（clang 还需 `__attribute__((fallthrough))`） |
| 8.4.a | 循环初值与终值不用魔数 |
| 8.4.b | 循环控制表达式中除 `for` 首尾子句的计数器外不赋值 |
| 8.5.b | 不用 `abort()`、`exit()`、`setjmp()`、`longjmp()` |

## 3. 格式与命名层（MCU profile 与选用 BARR-C 的 userspace）

| 规则 | 要点 |
| --- | --- |
| 1.2.a | 行宽 ≤ 80 |
| 1.3.a ★ / 1.3.b | 所有 `if/else/for/while/do/switch` 体加花括号；左花括号独占一行（Allman） |
| 1.5.a / 1.5.b | 少用缩写；项目维护缩写表 |
| 1.7.c / 1.7.d | 尽量不用 `goto`、`continue` |
| 2.1.a | 允许 `//` 单行注释 |
| 3.1.* | 关键字后加空格；二元/赋值/三元运算符两侧空格；一元运算符不加；`*`、`&` 在声明中两侧空格（`uint8_t * p_buf`）；函数定义名与 `(` 之间空格 |
| 3.2.* | 连续声明的变量名、结构成员名、赋值运算符对齐 |
| 3.3.a / 3.3.b / 3.3.c | 一行一条语句；自然代码块前后空行；文件以结束注释收尾（如 `/*** end of file ***/`） |
| 3.4.a / 3.4.b | 4 空格缩进；`case` 标签在 `switch` 内对齐缩进 |
| 3.5.a / 3.6.a / 3.6.b | 禁止 tab；只用 LF；除 LF 和换页外无其他不可打印字符 |
| 4.1.a ★ / 4.1.b / 4.1.c ★ / 4.1.d | 模块（文件）名全小写；前 8 个字符唯一；头文件名不与标准库头同名；含 `main()` 的模块名含 `main` |
| 4.2.a / 4.2.c.i | 每个源文件一个头文件；优先不在头文件中 `extern` 声明变量 |
| 4.4.a | 使用统一的 `.h`/`.c` 模板（见 `assets/templates/`） |
| 5.1.a / 5.1.b / 5.1.c | 新类型名全小写、以 `_t` 结尾；结构/联合/枚举通过 `typedef` 命名；公共类型带模块前缀 |
| 6.1.d–6.1.i | 函数名 ≤ 31 字符、全小写、下划线分词、描述用途（动词）、公共函数带模块前缀（`motor_set_speed`）；宏名全大写 |
| 6.2.a / 6.2.c | 函数尽量控制在一页（kit 阈值 100 行）；优先单一出口 |
| 6.4.a | 线程/任务函数名以 `_thread`、`_task` 或 `_process` 结尾 |
| 6.5.b | ISR 名以 `_isr` 结尾 |
| 7.1.c–7.1.i | 变量名不以下划线开头、≤ 31 字符、**≥ 3 字符（含循环计数器，用 `idx` 不用 `i`）**、全小写、不含别处定义的数字、下划线分词、描述用途 |
| 7.1.j ★ / 7.1.k ★ / 7.1.l / 7.1.m ★ / 7.1.n / 7.1.o | 全局 `g_`、指针 `p_`、指针的指针 `pp_`、布尔 `b_`、非指针句柄 `h_`；组合顺序 `[g][p\|pp][b\|h]_`（如 `gp_rx_buf`、`gh_imu_task`） |
| 7.2.b / 7.2.c | 局部变量在需要时定义；全局变量定义集中在文件顶部 |
| 8.1.a ★ | 变量声明中不用逗号 |
| 8.2.a / 8.2.b / 8.2.d | 较短分支在前；`if...else` 嵌套 ≤ 2 层；有 `else if` 的必须以 `else` 结尾 |
| 8.3.a ★ | 每个 `case` 的 `break` 与该 `case` 对齐 |
| 8.4.c / 8.4.d | 无限循环写 `for (;;)`；空循环体用含注释的花括号 |
| 8.6.a ★ | 变量与常量比较时常量在左：`if (NULL == p_buf)` |

## 4. 机械门禁

在目标仓库根目录放置 `assets/barr-c/.clang-format`、`.clang-tidy`、`.editorconfig`（已有同名文件时先比较，不要覆盖），然后：

```sh
# 只检查自有生产代码；排除 platform/ 厂商代码与 tests/（Ceedling 的 test_*.c 会触发 4.1.b 前 8 字符唯一性）
sh <skill>/scripts/barrc/check.sh $(git ls-files 'app/*.[ch]' 'module/*.[ch]' 'interface/*.[ch]' 'driver/*.[ch]' 'bsp/*.[ch]')
```

- 需要 clang-format ≥ 16、clang-tidy ≥ 17；有 `compile_commands.json` 时 clang-tidy 使用它（CMake：`-DCMAKE_EXPORT_COMPILE_COMMANDS=ON`）。
- 审查过的例外：在该行加 `// barr-c:allow` 注释，并在偏离记录中写明理由。
- 编译告警门禁（`assets/barr-c/COMPILER_FLAGS.md`）：

```text
-std=c99 -Werror=implicit-function-declaration -Wall -Wextra -Werror=parentheses
-Wfloat-equal -Wsign-compare -Wshadow -Wundef -Wswitch-default -Wimplicit-fallthrough -Wvla
```

- 门禁通过只说明机械部分合规；§2/§3 中的“代码审查”条目仍需逐条人工/Agent 审查，报告中分开写。

## 5. 2018 版勘误（应用时采用修正版）

- 5.4.b.i 的 `float32_t/float64_t` 并非 C99 类型（是 CMSIS-DSP 约定）；标准名为 `_Float32/_Float64`（TS 18661-3 / C23 Annex H）。项目已使用 CMSIS-DSP 类型时可沿用。
- 5.5 示例中在 `#if` 中用 `sizeof` 无效；用 `static_assert(8 == sizeof(timer_reg_t), "...")`（C11，C99 项目可用编译器扩展或负数组技巧，并记录）。
- 3.1.b 赋值运算符列表应包括 `<<=`、`>>=`，不包括 `~=`、`!=`。
- 1.8.c.ii 线程共享数据用 `volatile` 的建议已撤回（见 §2）。

## 6. 生成代码政策（Barr Group 为 2026 版预发布的四条）

1. 生成代码就是代码，适用全部规则，无豁免。
2. 每个含生成代码的提交都有一位读完全部代码并负责的具名人类作者；生成工具自己的审查不算审查。
3. 提交信息或文件头记录生成工具及版本。
4. 静态分析是门槛：合并前新增发现为零。
